# COMP 345 Term Project: Frozen LLM Embeddings Need Not Beat TF-IDF for Cuisine Classification from Ingredient Lists

Ruoyu Gu, COMP 345, Fall 2026. This repository holds the midterm (Checkpoint 2) submission.

**Question.** What does a frozen foundation-model embedding add beyond a strong, task-specific lexical
representation? We predict one of 20 cuisines from a recipe's ingredient list and compare two
representations under the same PyTorch linear softmax probe:

- **TF-IDF** (baseline), fit on each training subset only.
- **Frozen Gemini embedding**, `gemini-embedding-001`, task type `CLASSIFICATION`, 768 dimensions.

Both use the same normalized ingredient text, the same group-aware three-fold splits, and the same
eight training proportions (2-100%).

| Method (100% training) | Test macro-F1 (mean ± fold SD) | Accuracy |
| --- | --- | --- |
| TF-IDF | 0.7048 ± 0.0053 | 0.7820 |
| Frozen Gemini embedding | 0.6462 ± 0.0135 | 0.7631 |

Embedding minus TF-IDF: -0.0586, 95% group-bootstrap interval [-0.0652, -0.0523].

## Not in this repository

- **Dataset.** Download `train.json` from Kaggle's [What's Cooking](https://www.kaggle.com/c/whats-cooking)
  into `data/whats-cooking/` (see the README there). Only the labelled `train.json` is used.
- **Gemini embedding cache** (`artifacts/gemini-embedding-001.npz`, about 110 MB) and **prediction archive**
  (`artifacts/results/predictions.npz`, about 200 MB). Both exceed GitHub's file-size limit and are
  regenerated by the commands below.

The demo notebook runs from a fresh clone without either: it skips the sample-recipe and cache checks
when those files are missing and reads everything else from `artifacts/midterm/`.

## Computational resources

The full run was executed on Windows 11 with a 32-thread CPU and CPU-only PyTorch; no GPU is needed.
It took about 2 hours 18 minutes, with a peak Python working set of about 4.3 GB. Plan for 8 GB RAM and
1 GB of free disk. The Gemini API is the only network stage and needs `GEMINI_API_KEY`; everything after
the cache exists runs offline.

## Run it

From the repository root (PowerShell syntax):

```powershell
python -m pip install -e ".[dev,report]"
pytest -q

# Open the demo (no data or API key needed)
jupyter notebook demo/COMP345_midterm_demo.ipynb
```

To reproduce the results from scratch:

```powershell
# 1. Frozen splits
python scripts/run_project.py prepare-splits --data data/whats-cooking/train.json --output artifacts/splits.json

# 2. Gemini embedding cache (the only API stage; resumable, 100 recipes per call by default)
python -m pip install -e ".[gemini]"
$env:GEMINI_API_KEY = "..."
python scripts/run_project.py generate-embeddings --data data/whats-cooking/train.json `
  --output artifacts/gemini-embedding-001.npz --start-index 0 --end-index 100
#    repeat with the next --start-index/--end-index range until all 39,774 recipes are cached

# 3. Experiment, failure analysis, midterm tables and figure
python scripts/run_project.py run-experiment --data data/whats-cooking/train.json `
  --splits artifacts/splits.json --embeddings artifacts/gemini-embedding-001.npz --output-dir artifacts/results
python scripts/analyze_results.py artifacts/results/results.json --data data/whats-cooking/train.json `
  --splits artifacts/splits.json --predictions artifacts/results/predictions.npz `
  --output-dir artifacts/results/failure-analysis
python scripts/export_midterm_artifacts.py artifacts/results --output-dir artifacts/midterm
python scripts/make_midterm_figures.py artifacts/midterm/results.json --output-dir report/figures
```

The experiment runner also contains the probability-fusion and feature-fusion arms planned for the final
stage. `export_midterm_artifacts.py` keeps only the TF-IDF and Gemini arms reported at the midterm.

TF-IDF alone can be run without an API key:

```powershell
python scripts/run_tfidf_baseline.py --data data/whats-cooking/train.json `
  --splits artifacts/splits.json --output-dir artifacts/tfidf-baseline
```

Rebuild the report:

```powershell
xelatex -interaction=nonstopmode -halt-on-error -output-directory report report/midterm_report.tex
xelatex -interaction=nonstopmode -halt-on-error -output-directory report report/midterm_report.tex
```

## Design notes

- Identical normalized ingredient lists form a group and never cross a split, so duplicate recipes cannot
  leak between training and test.
- The TF-IDF vocabulary is fit on each training subset only; test folds are never used for fitting or
  model selection.
- The Gemini API is called only by `generate-embeddings`. The cache is checked for shape, finite values,
  recipe-id order, and a metadata fingerprint before evaluation reads it.
